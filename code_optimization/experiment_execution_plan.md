# 实验执行方案

## 1. 实验目标与公平性原则

实验比较以下已有算法：

- Random
- MaxResource / LB
- LocalFirst / LPD
- RTBL
- RDODA-DSSA，对应代码中的 `proposed`
- C-RDODA-DSSA，对应代码中的 `customized`

每个“场景 × 重复编号”使用相同随机种子重新创建环境，使各算法面对相同的节点属性、链路属性、DNN DAG 和请求约束。每组实验默认重复 10 次，报告均值和样本标准差。

统一指标为：

- 平均估计推理时延
- 平均动态运行可靠性
- 平均动态精度可靠性
- 平均总能耗
- 拒绝或失败部署数
- 算法运行时间

原始结果写入 `raw_results.csv`，聚合结果写入 `summary.csv`。任务 ID 会被记录，因此重复执行同一命令可断点续跑。

注意：当前 `RTBLRunner` 不推进动态时隙，且总能耗固定返回 `0`。因此默认仅在整体性能实验中保留 RTBL 作为旧口径参考，不应使用其能耗结果与其他算法作结论性比较；动态退化实验默认排除 RTBL。

## 2. 默认参数与选择依据

| 参数 | 默认值 | 选择依据 |
|---|---:|---|
| 种群规模 | 60 | 在搜索多样性与单次运行成本之间折中，沿用现有实现默认值 |
| 迭代次数 | 120 | 沿用当前可执行入口的默认值，避免使用代码中未实际采用的 `gen=1000` |
| 变异概率 | 0.10 | 沿用现有算法默认值 |
| 交叉概率 | 0.50 | 沿用现有算法默认值 |
| 重复次数 | 10 | 用于计算均值和样本标准差；正式论文实验建议增加到 20 或 30 |
| 基础随机种子 | 20260613 | 固定种子保证可复现 |

## 3. 可直接执行的实验

### 3.1 不同 DNN 数量下的整体性能

自变量：DNN 请求数 `5, 10, 20, 30, 40`。

```bash
python experiment_runner.py \
  --suite overall \
  --dnn-counts 5,10,20,30,40 \
  --repeats 10
```

重点观察可靠性随请求负载增加的下降幅度、失败数增长速度，以及时延、能耗和运行时间的变化。

### 3.2 动态可靠性退化实验

弱、中、强场景同时调整节点可靠性退化、链路可靠性退化和热度遗忘系数：

| 场景 | 节点退化参数 | 链路退化参数 | 热度遗忘系数 |
|---|---|---|---|
| Weak | 默认值的约 0.5 倍 | 默认值的约 0.5 倍 | 0.50 |
| Medium | 使用现有环境默认值 | 使用现有环境默认值 | 0.70 |
| Strong | 默认值的约 1.5 倍 | 默认值的约 1.5 倍 | 0.90 |

```bash
python experiment_runner.py \
  --suite dynamic \
  --dnn-count 20 \
  --repeats 10
```

重点观察动态运行可靠性、动态精度可靠性和失败部署数。预期 C-RDODA-DSSA 在强退化场景中的下降幅度更小。

### 3.3 遗传算法参数敏感性

采用单因素控制法，其他参数保持默认：

- 种群规模：`20, 40, 60, 80, 100`
- 迭代次数：`30, 60, 120, 180`
- 变异概率：`0.05, 0.10, 0.20, 0.30`

```bash
python experiment_runner.py \
  --suite sensitivity \
  --algorithms proposed,customized \
  --dnn-count 20 \
  --repeats 10
```

比较性能收益是否趋于饱和，并结合运行时间选择默认超参数。

## 4. 建议绘图与统计检验

- 折线图：DNN 数量或参数值为横轴，六项指标为纵轴，误差棒使用样本标准差。
- 动态退化实验：使用分组柱状图。
- 对同一场景、同一随机种子的算法结果使用配对 Wilcoxon 符号秩检验。
- 同时报告相对改进率，例如相对 RDODA-DSSA 的失败数下降比例和可靠性提升比例。

## 5. 当前代码尚不支持的实验

- Pareto 前沿质量：现有运行函数只返回最终选中解，没有导出最终非支配解集，因此暂不能可靠计算 Hypervolume。
- 消融实验：定制初始化、DAG block crossover、skew mutation 和 elite local search 尚无独立开关。
- 大规模网络：`core/topology.py` 当前固定生成 1 个云、10 个边缘节点和随机用户节点，尚未提供 Small/Medium/Large 可扩展拓扑接口。
- 应用偏好场景：最终解选择权重目前写在算法内部，尚未暴露 Delay/Reliability/Energy/Balanced 配置。
- RTBL 动态统一评价：当前 RTBL 尚未接入运行队列、动态可靠性刷新和总能耗统计。

这些实验应在对应算法接口显式参数化后开展，避免通过临时修改代码造成不可复现或比较口径不一致。
