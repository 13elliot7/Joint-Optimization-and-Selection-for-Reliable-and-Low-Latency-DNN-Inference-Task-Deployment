Reviewer#1, Concern#3: In Equation (6), task service reliability is defined as a
product over all deployed layers and nodes. This implicitly assumes independent
failures and effectively multiplies reliability for each layer execution. For models with
many layers, the value can become extremely small even if each node is highly
reliable.

Author response:
Thanks for identifying this modeling weakness. We have reformulated service
reliability to avoid repeatedly multiplying the reliability of the same node for multiple
layers deployed on that node. In the revised model, the service reliability of a DNN
request is calculated over the unique computing nodes and unique
communication links used by the deployment strategy. This formulation better
reflects the fact that when several subtasks are placed on the same node, a node failure
affects them jointly rather than independently.

Author action:
We revised the reliability model in Section 4. The revised service reliability model
includes both node reliability and link reliability, and it is defined over the sets of
used nodes and traversed links.

Reviewer#1, Concern#5: The reliability model assumes that node reliability
parameters remain constant during task execution. However, in the experiments,
reliability values are randomly drawn from intervals. It is unclear whether these
values are fixed per node across all tasks or re-sampled across runs.

Author response:
Thanks for pointing out the ambiguity. The revised model explicitly distinguishes
initial service quality from dynamic service quality. Each node has an initial service
reliability and initial inference accuracy sampled at the beginning of a simulation
instance. During online execution, these values evolve according to the current node
load and heat state.
